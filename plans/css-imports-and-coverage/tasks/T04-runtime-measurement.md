# T04 — Honest runtime coverage pipeline

Status: complete. Blocked by: T03. Coverage: R4; AC4.

Build the smallest JVM adapter around the pinned Closure AST and Chromium/ChromeDriver that records original-Java line and branch evidence. Built-in branch instrumentation omits ternaries and short circuits; use explicit unoptimized statement/function-entry and complete branch probes instead, with token-level mapping and distinct same-line branch identities. Verify conditional expressions, short-circuit values/single evaluation, loop exits and switch fallthrough/default/unmatched behavior without counting injected helpers. Unsupported owned branch forms fail closed. Demonstrate an end-to-end runtime target with untouched methods and partially exercised if/ternary/short-circuit/switch/loop branches included in its denominator, including multiple Java origins sharing a generated line and a single multiline expression. Keep a complete independent JVM-compilation line inventory as the browser denominator, validated against the declared Java sources/declarations; never copy JVM hits into browser obligations. Missing browser map origins remain zero-hit obligations. Java-AST expression-completion attribution may recover unconditional interior origins only when successful completion proves execution on the same path; skipped alternatives, throwing operands and deferred lambda/class bodies must never inherit hits. Actual J2CL multiline controls (including ReactElement lines 120/136 omitted by its maps), independent expected inventories and counter-free controls must prove those obligations remain enforced. Preserve all owned modules without dead-code pruning and verify stable attribution and failure controls. Create a source-aware runtime LCOV from disjoint browser obligations and parsed @GwtIncompatible JVM-only declarations, including mixed-platform files. Reject missing JVM-only method evidence and ambiguous attribution; prove both omitted and unexecuted JVM-only code fail the actual root gate even with complete browser coverage. Route explicit effective JVM/runtime report names per root in JSON, pass a report directory to the checker, and wire tools/check.sh; preserve no-data and per-class checks. Keep reports separate and reject missing/corrupt inputs. Verify native browser boundaries and API instrumentation limitations before expanding tests.

Evidence: all five verification targets (`coverage_tests`, `lcov_report_tests`, `browser_coverage_tests`, `instrumenter_tests`, `runtime_coverage_tests`) pass. Real Chromium/J2CL controls assert ternary/short-circuit/for/while/do/switch/assertion outcomes, enhanced-for exits, conservative ambiguous-expression coverage, skipped/throwing/deferred bodies, complete independent line inventories, whole JVM types and mixed JVM methods. Complete mixed-platform execution passes the actual 95/85 gate; identical browser counters with unexecuted JVM bodies fail it. Missing/corrupt maps, sources, method inventory and counters fail collection. The real runtime CLI passes against the full raw JVM report; ReactElement lines 120/136 are independently absent from its map, present among all 50 bytecode line obligations, and covered through successful unconditional expression completion. Formatting, buildifier, shell syntax and diff checks pass. Root floors remain unchanged; T05 supplies the remaining behavioral coverage.

Implementation detail: SORT_ONLY orders every supplied module without pruning. Exact original module bytes establish bundle intervals, and declared per-module maps anchor probes to Java AST declarations/expressions. A unique same-expression Java decision can resolve coarse statement mappings; ambiguous matches retain zero-hit obligations. Native JS source entries are validated as declared sidecars and contribute no Java hits. The source inventory comes from declared authored Bazel sources, including sources with no execution counters.
