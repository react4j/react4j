# Unified CSS imports and complete coverage

## Source and authority
The user asked “Could you do all of these things” after accepting the preceding recommendation: unify @CssImport across keyframes, globals and component selectors; retire @CssIncludes; retain imported kinds across library headers; distinguish valid peer reference cycles from invalid global inclusion cycles; and close the measured coverage gaps with every source root enforcing 95% lines / 85% branches. Implementation is authorized with no human plan checkpoint. Existing draft PR #112 remains draft and must not be merged. JVM-only build tools, react4j.css namespace, package-local explicit Java/Closure sources, Yoda comparisons and permanent reader-facing docs remain constraints. Leave etc/secrets untouched.

## Outcomes
R1: One checked Java import annotation covers all resource kinds. Global imports require no alias and activate whenever their importer is retained. Keyframe and component imports require aliases and retain resources only when the corresponding animation/selector syntax uses them. No separate kind flag duplicates the target's unique declaration annotation.
R2: Component styles can select explicit imported peers through descendant, child and sibling relationships while preserving checked local ownership. Imported selectors resolve to stable generated roots and work across separately compiled/header-only Java libraries. Ordinary strings, attributes and declaration values are never rewritten as selector references.
R3: Resource retention and global ordering remain distinct. Used peer references may cycle; global inclusion cycles remain errors. Resources emit once, unselected globals/unused imports stay absent, legacy shared inputs precede globals, globals precede component rules, and deterministic dependency-first global precedence is preserved. Component discovery remains conservative; Closure liveness extraction is not part of this delivery.
R4: All six configured roots and existing class floors pass 95% line / 85% branch coverage against meaningful execution evidence. Preserve the thresholds, missing-source failures and denominator integrity. Do not lower floors, exclude owned executable code to improve numbers, fabricate hits, or replace owned production implementations with test shims.
R5: Relevant examples demonstrate global imports and actual peer styling; processor/compiler/bundler corner cases, separate compilation and source maps are extensively tested. Permanent guide/changelog and the draft PR describe the final behavior and measurement boundaries.

## Verified evidence
Current @CssImport validates Keyframes only, while CssIncludes stores ordered global dependencies. Css has SOURCE retention; Keyframes/GlobalCss have CLASS retention because Bazel header jars omit sidecars. The bundler rejects all graph cycles and component dependency targets. Component selectors currently require a leading & and target the same element. The current JVM LCOV report has core 40.65/31.11%, dom 1.07/70%, css/processor 53.64/56.96%; the other roots exceed 95/85. CssProcessor/CssGenerator/CssDescriptor report zero hits: packaged tests load a non-instrumented processor jar via --processor-path and data dependencies. Core/DOM contain native browser methods (React.currentOwner, JsPropertyMap factories and native property accessors), so meaningful execution of those paths requires the browser. Chromium and ChromeDriver are already pinned. Disposable probes of pinned Closure v20260913 confirmed its Java coverage-only mode preserves unused functions, but its branch pass omits conditional expressions and short-circuit decisions. The pinned callback handles if/loop structures only. Built-in per-generated-line counters also cannot distinguish multiple Java origins sharing a generated line. Those counters alone cannot establish the required denominator; T04 must prove explicit AST probes with token-level Java attribution before runtime test expansion.

## Technical decisions
D1: CssImport.name defaults to empty. Global targets require empty names, named targets require valid aliases, all aliases share a local namespace, and incompatible/duplicate/unsupported combinations fail before the owner's outputs are emitted. Named imports are checked even when unused. Remove CssIncludes and migrate all examples/tests; no compatibility path for unshipped APIs. Css becomes CLASS-retained like the other declarations, with the same JVM/header annotation-text tradeoff and no runtime registration.
D2: Use :css(alias) as a compiler selector reference, resolved through the parsed CSS selector model. Component selectors still start with &. Each later compound separated by whitespace, >, + or ~ must start with an imported component reference, followed only by checked state/attribute qualification; raw global/descendant classes, local modifier names on peer compounds, repeated &, unqualified targets and peer references inside selector functions are rejected in this initial contract. Existing same-element :is/:not/:where support remains. Global styles may use peer references in otherwise ordinary selectors and their supported selector functions. Imported peer modifier accessors are deferred: this delivery imports roots only. Alias matching is case-sensitive and the pseudo name is case-insensitive. Quoted, escaped, multiple, missing or wrong-kind reference arguments are errors.
D3: Keep one resource sidecar identity/dependency contract, inferring edge semantics from target kinds. Compute retained closure with a visited set that allows component reference cycles; order global nodes with DFS over global-to-global inclusion edges only. Visit explicit global roots first, then requirements of retained components in owner order, then remaining retained globals in owner order. Each node emits at its first completed ordered visit. Keyframe nodes have no dependencies. Validate every retained edge, source-map triple and metadata identity; no old-format fallback is introduced.
D4: Measure compiler/tool roots with JVM coverage, using the actual instrumented implementation as well as the assembled-jar contract tests. Core and DOM runtime roots need browser execution coverage through the existing pinned Chromium and a JVM adapter using the pinned Closure JavaScript AST, with token-level Java-source map attribution. Insert explicit statement/function-entry and branch probes into the unoptimized parsed tree rather than use Closure's incomplete built-in coverage pass. This additional code is required by the verified omissions, uses the existing compiler dependency and introduces no new execution engine or JS package toolchain. Keep raw JVM and browser reports separate. Build one source-aware runtime report for core/DOM: browser obligations for browser-executable code plus JVM obligations for parsed @GwtIncompatible declarations, including marked methods inside mixed-platform files and marked whole types. These source obligations are disjoint; never OR counters from different platforms or merge incompatible branch identifiers. Every owned executable declaration remains assigned to its actual execution platform. The JSON names the effective report per root (jvm.lcov or runtime.lcov); CoverageCheck receives the config, report directory and summary path, validates required report names and routes each rule explicitly. No old CLI fallback. Browser coverage compilation includes all owned modules without dead-code pruning, records untouched methods/branches as uncovered, and reports original Java identities. Branch obligations include both if/conditional-expression outcomes, short-circuit paths (&&, || and nullish coalescing where present), loop conditions and switch case/default entries. Switch fallthrough counts entry into each reached arm, as JavaScript case-entry coverage, rather than claiming dispatch-only coverage. Preserve operand values, evaluation order and single evaluation of side effects; add a default probe for unmatched switches. Unsupported owned branch forms fail closed. Take the complete executable Java line denominator from the JVM compilation's line inventory, independently of browser maps/hits, and validate source/declaration completeness against the declared source inventory. This inventory supplies obligations, never browser hits. Project statement/function-entry/expression-completion probes to those identities; merge hits only within a single platform's same source line. Missing map origins remain present with zero hits, so incomplete mapping can cause a conservative failure but cannot improve coverage. For a mapped expression that omits interior Java origins, allow Java-AST attribution only when successful completion proves those interior origins executed on the same unconditional path; exclude conditional/short-circuit alternatives and deferred lambda/class bodies from this inference. Ambiguous correspondence receives no hit proof. Preserve every obligation even when no safe attribution rule applies. Stable AST probe identities preserve distinct branch obligations on the same Java line. Do not count injected counter helpers as owned code. The browser collector and any report adapter run on the JVM; no Node/Selenium/new JavaScript package toolchain. JVM-only configuration behavior receives focused JVM tests, and its line/branch obligations contribute to the enforced runtime root totals rather than remaining ungated. This measurement boundary is documented for contributors.
D5: Runtime coverage uses the instrumented generated JavaScript for the real authored runtime code, real React assets and Chromium. Source maps determine ownership and line attribution; unmapped generated framework/helper code does not masquerade as owned Java evidence. Parse authored source ranges and use declared module/source inventories to assign disjoint obligations. JVM-only declarations must have their coverage evidence present even when the browser report is complete. The collector fails for missing/malformed counters/maps, absent expected owned modules/line inventory or JVM-only method evidence, invalid/ambiguous claimed source attribution or browser failures. A present authored line whose execution cannot be proved stays uncovered; it is never dropped or inferred covered from a nearby line. Failure to reach the root floor with this conservative evidence returns to measurement planning rather than changing the denominator. It proves its denominator with deliberately unexecuted owned methods, partially executed branches including ternaries/short-circuit decisions/switch arms/loops, multiple original lines on one generated line and inside a single multiline expression (including a conditionally skipped operand and an operand after a throwing expression), a mixed-platform class with unexecuted JVM-only methods, and omitted JVM-only evidence; those controls must fail the same root gate. Use actual J2CL output for multiline controls: current ReactElement$$Overlay maps omit executable Java lines 120 and 136 while the JVM line inventory retains them. Expected-map/line-inventory assertions must detect missing origins independently of counter production, verify omitted lines stay in the denominator, and prevent false hits from skipped/throwing operands or deferred bodies. Explicit behavioral controls verify short-circuit side effects, retained expression values, switch fallthrough/unmatched/default behavior, early loop exits and thrown operands, so instrumentation cannot make a test pass by changing execution. No hand-maintained source exclusion list is allowed. Validate this small end-to-end seam in T04 before expanding runtime tests. If the pinned AST/source-map APIs cannot provide reliable obligation inventories and sufficient safe execution proof to satisfy the required floors, or the instrumentation cannot preserve semantics, return to planning with concrete probe results rather than silently changing measurement semantics.
