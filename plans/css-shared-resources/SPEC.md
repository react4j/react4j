# Shared CSS resources

## Source and authority
The user accepted the preceding discussion and instructed implementation with relevant example usage and extensive processor corner-case coverage. Earlier constraints remain: JVM-only processing; react4j.css namespace; package-local explicit source lists; Yoda equality; generated Java through the existing generator; preserve draft PR #112 and do not merge it.

## Outcome and scope
R1: Independently declared, automatically namespaced keyframes can be imported through checked Java type references into component or global CSS, including across separately compiled libraries. Actual animation references create resource dependencies; unused imports do not retain keyframes.
R2: Global CSS is available without automatically activating it. Each bundle selects global definitions explicitly, in declared order. Components and globals can explicitly depend on global definitions. Missing dependencies, wrong resource kinds, malformed metadata and dependency cycles fail clearly. Shared resources emit once.
R3: Existing component behavior remains unchanged. Component collection stays conservative at build-target granularity; Closure liveness extraction is outside this pass. Global definitions are retained as complete units. No runtime registration, initialization or interpolation is introduced.
R4: Processor diagnostics, separate compilation, source maps, bundling and browser behavior have substantial coverage; public documentation and changelog describe downstream behavior.

## Decisions
- Add @Keyframes (a frame body), @GlobalCss (a complete stylesheet), repeatable @CssImport(name, value) for animation aliases, and @CssIncludes(Class<?>[]) for required globals. Keyframes and GlobalCss declaration annotations use CLASS retention so resource kinds can be checked through Bazel header jars. Imports/includes remain source annotations; existing @Css remains source-retained. CSS declaration text consequently remains in JVM classfiles/header jars; these annotations introduce no runtime registration or JavaScript initialization. This avoids a custom header-compilation pipeline. Resource marker classes are accessible, non-generic classes extending Object; nested definitions are static. They declare no fields, explicit constructors, initializers or abstract methods. Concrete/static helpers are allowed. @Css keeps its existing class contract.
- Preserve the current supported at-rule subset: global style rules, media and supports. Shared keyframes are declared separately and imported. Do not add font-face, container queries or dynamic animation names.
- Emit per-owner .css.json metadata beside .css and .css.map. It contains version, binary Java owner, kind and resolved dependencies; dependencies use actual parsed animation references plus explicit global includes. The existing J2CL resource retention patch also retains this suffix. Imports validate retained declaration annotations, including through separately compiled header jars. Bundling validates sidecar metadata and the emitted resource graph. Processor validation must not require resource sidecars on the Java compilation classpath, because Bazel header jars omit them.
- css_bundle gains globals, an ordered list of binary Java owner names. This selects individual definitions even when a library contains many globals. Missing/wrong-kind roots fail. Bazel dependencies remain candidate discovery only. This explicit build-facing string identity avoids another extraction rule/provider layer; annotation references remain type checked.
- Bundling traverses dependencies from all collected component definitions and explicitly selected globals, rejects cycles/missing resources, emits each reachable definition once, places globals before components in the shared layer, and emits referenced keyframes once. Legacy shared files emit first. Global definitions use dependency-first depth-first traversal, visiting explicit roots in declared order followed by conservative component roots in owner order; each definition emits at its first completed visit. Thus a dependency shared with a later root is emitted before its first consumer, not re-emitted at the later root position. This deterministic precedence takes priority over independent root ordering when roots overlap dependencies. Legacy shared CSS inputs keep their existing ordering and behavior.
- Keep parser/source-map handling shared. Parse animation grammar before resolving aliases; aliases that collide with local definitions or reserved names are diagnosed. Invalid targets and unsupported annotation combinations are diagnosed before their resources are emitted.

## Acceptance and testing
AC1 (R1): Same-compilation and separate-library imports work; multiple aliases, shorthand keyword collisions, lists, local/import collisions, unused imports, inaccessible/wrong-kind types and header-jar imports are covered. Malformed/missing metadata is checked at the bundler boundary, including missing resources from libraries compiled without the processor. Generated identities remain stable and collision safe.
AC2 (R2): Two bundles over the same candidates can select different globals; unselected globals and unused keyframes are absent; shared dependencies appear once; ordered cascade behavior including overlapping roots/dependencies and legacy shared files, missing roots/dependencies, cycles, metadata validation and map pairing are tested.
AC3 (R3): Existing goldens and browser tests still pass; resource-only definitions emit no Java subclasses or runtime registration. Existing generated Java conventions remain unchanged.
AC4 (R4): Relevant browser examples use shared keyframes and selected globals and verify rendered/animated behavior in development and optimized modes. Processor tests cover owner shapes, annotation combinations, literal restrictions, aliases, includes and compiler grammar variations, using exact goldens for representative cases plus constraint matrices. Unit coverage remains gated by the full tools/check.sh gate. README and changelog document author use and limitations.

## Risks and verification
Metadata crosses compilation and bundling boundaries: validate structure and identity rather than trusting paths. Source maps must still resolve to authored Java. Global ordering is observable: tests must compare computed CSS, not only source strings. Current component retention is conservative and must not be described as Closure dead-code elimination. Evidence-driven revision: the cross-library integration build failed with Missing CSS metadata while resolving SharedPulse from a Bazel header jar. CLASS-retained resource declarations address this; the tradeoff is retaining their annotation text in JVM classfiles. No unresolved user decision remains.
